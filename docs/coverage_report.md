## Function Coverage Notes

The function coverage percentages appear artificially low due to a known limitation of `llvm-cov` with the Soroban SDK's `#[contractimpl]`/`#[contractimpl(contracttrait)]` macros:

### The `_RNCNv` dispatch wrapper issue

The contract macros generate closure-based dispatch wrappers (`_RNCNv` prefix in llvm-cov) for each contract function. These wrappers are the entry point called by the Soroban host environment. llvm-cov cannot trace execution into these closures because they are invoked through the Soroban host's dispatch mechanism, not directly from Rust code.

**Key point**: affected functions have their **bodies fully covered** (verified via line coverage). The dispatch wrapper closure is the only uncovered part.

### The `try_from`/`try_from_val` issue

These are auto-generated trait implementations from `#[contracttype]`/`#[contractevent]` for ScVal serialization. They are invoked internally by the Soroban host during argument passing and return value conversion, but llvm-cov cannot trace them. These are not real business logic functions.

### Conclusion

**Line coverage is the accurate metric.** The adjusted line coverage of **99.24%** reflects the true state of test coverage. Function coverage is misleading due to Soroban SDK + llvm-cov interaction limitations.

## Function Coverage Notes

The function coverage percentages appear artificially low due to a known limitation of `llvm-cov` with the Soroban SDK's `#[contractimpl]` macro:

### The `_RNCNv` dispatch wrapper issue

The `#[contractimpl]` macro generates closure-based dispatch wrappers (`_RNCNv` prefix in llvm-cov) for each contract function. These wrappers are the entry point called by the Soroban host environment. llvm-cov cannot trace execution into these closures because they are invoked through the Soroban host's dispatch mechanism, not directly from Rust code.

**Impact by contract:**

| Contract | Functions | Uncovered `_RNCNv` | Uncovered `try_from` | Uncovered upgrade | Real uncovered |
|----------|-----------|---------------------|----------------------|-------------------|----------------|
| crowdsale| 32 | 0 | 7 | 1 | 0 |
| payout   | 59 | 10 | 11 | 1 | 0 |
| token    | 22 | 0 | 1 | 1 | 0 |

**Payout's 10 uncovered `_RNCNv` wrappers** are all view functions (read-only): `get_distribution`, `get_investor_count`, `get_total_claimable`, `get_claimable_amount`, `get_distribution_summary`, `is_distribution_claimable`, `get_required_funding_amount`, `get_distribution_available_funds`, plus two macro-generated inner functions (`take_onchain_snapshots_`, `_set_investor_balances_internal`).

**Key point**: All 10 functions have their **bodies fully covered** (verified via line coverage and `_RNv` function counts > 0). The dispatch wrapper closure is the only uncovered part. Attempted calling via `e.invoke_contract()` directly — no improvement.

**Why crowdsale/token don't have this issue**: They have fewer view functions. Their `_RNCNv` wrappers are primarily for write functions (with `#[when_not_paused]`/`#[only_owner]` macros), which are covered because the macro-generated outer wrapper takes a different code path.

### The `try_from`/`try_from_val` issue (13 functions across all contracts)

These are auto-generated trait implementations from `#[contracttype]` for ScVal serialization. They are invoked internally by the Soroban host during argument passing and return value conversion, but llvm-cov cannot trace them. These are not real business logic functions.

### Conclusion

**Line coverage is the accurate metric.** The adjusted line coverage of **99.22%** reflects the true state of test coverage. Function coverage is misleading due to Soroban SDK + llvm-cov interaction limitations.
